# Catalogue media audit

Current asset handling is local-only and rejects remote URLs. V4 migration 20 records explicit `visual_key` values for known packaged artwork and the booking UI resolves only the saved custom image or saved key. Unknown/missing visuals render an intentional non-image state; they never become a shirt through text matching.

The audit is now executable with `npm run audit:garment-assets`; the current T1 fixture reports 32 active rows, 26 exact visuals, 6 explicitly intentional shared visuals, zero missing/invalid/broken paths, and zero derivative-budget warnings. `npm run audit:garment-assets:contact-sheet` generates [the review sheet](./CATALOGUE_MEDIA_CONTACT_SHEET.html), containing every active garment, human-readable category, visual key, resolved asset and thumbnail. Without an explicit `EPIC_AUDIT_DB_FILE`/`EPIC_DB_FILE`, that command seeds a disposable V4 demo database and deletes it afterwards; it never falls back to a developer's home-directory database. Supplying an explicit database is the deliberate path for auditing an existing workspace.

Thirteen previously incorrect or overly generic mappings (handbag, towel, curtain, carpet/rug, soft toy, socks, Sherwani, Blouse, Salwar suit, Lehenga, Tie/Scarf, Pillow Cover and Quilt/Duvet) now use dedicated original Epic/Lndry artwork. Every active runtime image now uses a 256px WebP derivative; PNG masters have moved to `assets/garments/masters/` and are no longer packaged with the runtime. On 11 September 2026, the generated sheet was rendered and reviewed in four visual batches: all 32 thumbnails loaded, each category/key/asset pairing was present, and no visibly wrong garment mapping was found. Polo/Formal shirt, Jacket/Coat, Kurta pyjama, Table cloth and Uniform set are documented **intentional shared close-family visuals**, not missing artwork. Catalogue media path, sizing and visual-mapping readiness is therefore **VERIFIED_CURRENT**; future additions remain subject to the same contact-sheet gate.
